# Demo place: "Universe at Home: Meadow"

A Roblox place that shows the whole system working at once: a procedurally generated landscape, grass built in three rings by this project's own pipeline, many Actors in parallel, and a stress-test bench with a live metrics HUD. It ships as `build/UniverseMeadow.rbxlx` (open it in Studio directly) and as a Rojo project for development.

Everything here is a design target for the build; claims about engine behaviour that the audit marks NOT PUBLICLY SPECIFIED are wrapped in capability checks with visible fallbacks, because nobody can run Studio in the build environment.

## 1. Layout

| Place location | Source | Role |

| `ReplicatedStorage.Demo` | `demo/shared/` | Deterministic generators shared by server and client: Config, WorldGen, GrassGen, SkyGen, Net (remote protocol), Metrics |
| `ReplicatedStorage.Demo.Assets` | generated by `tools/build_demo.sh` | ALLAN models and trees from `assets/liquid/` as ModuleScripts returning buffers |
| `ServerScriptService.Server` | `demo/server/` | World generation coordinator, sky and rock baking, ALLAN server training, determinism referee |
| `ServerScriptService.Workers` | `demo/server/workers/` | Server Actors (worldgen, rocks, training) |
| `StarterPlayerScripts.Client` | `demo/client/` | Client coordinator: HUD, grass rings, ground clipmap, stress bench |
| `StarterPlayerScripts.Workers` | `demo/client/workers/` | Client Actors (tile rendering, grass geometry, wind) |
| `Lighting` | project file | `Technology = Future`, golden-hour `ClockTime`, `Atmosphere`, `Sky`, `ColorCorrection`, `Bloom`, `SunRays`, `DepthOfField` |
| `Workspace` | project file | `StreamingEnabled = false`, `Terrain` with `Decoration = true`, tuned `GrassLength`, water colours; `Clouds` under `Terrain` |

## 2. The landscape (server)

- **Heightmap.** 1024 x 1024 studs at 4-stud voxels (256 x 256 columns, heights up to 256 studs). Deterministic `MyMath` fractal value noise with domain warping and ridged mountains, a carved river and a lake, then a few iterations of thermal erosion. Pure Luau in `demo/shared/WorldGen.luau`, so the CLI tests it here.
- **Biomes by height and slope.** Water, sand and mud shores, `Grass` and `LeafyGrass` meadows, `Ground` hills, `Rock`/`Slate` cliffs by slope, `Snow`/`Glacier` peaks. `Terrain:SetMaterialColor` tunes the palette.
- **Parallel generation.** 8 server Actors compute chunk material and occupancy arrays in the parallel phase (`BindToMessageParallel`); arrays come back by `SendMessage`; the coordinator calls `Terrain:WriteVoxels` serially (the API is Unsafe in parallel), time-sliced with progress replicated to clients.
- **Rocks.** Noise-displaced icospheres built as `EditableMesh` on the server (native codegen), baked with `CreateDataModelContentAsync` so they replicate as static content and cost clients no editable budget. Fallback: unbaked `MeshPart`s or skip with a HUD note.
- **Sky.** Six procedural skybox faces (gradient, sun matched to `ClockTime`, noise clouds) rendered on the server, baked and assigned to `Sky.Skybox*Content`. Fallback: default sky.

## 3. Grass: three Saturn rings around the camera

| Ring | Distance | Technique | Where the cost goes |
|---|---|---|---|
| 0 | 0 to 24 studs | **Blade geometry**: `EditableMesh` patches of 8 x 8 studs, 600 to 1500 curved, tapered blades of 4 to 6 triangles, vertex colours from root to tip with hash-noise hue variation and clumping cells; no transparency | Geometry built by client Actors in parallel, mesh calls serial |
| 1 | 24 to 96 studs | **Shell grass**: 8 to 16 stacked terrain-conforming skins, each with an alpha mask `EditableImage` of blade cross-sections at that height, rendered by the flawless rasterizer; shell 0 is opaque and carries the ground texture | GPU overdraw, almost no CPU |
| 2 | beyond 96 studs | Engine terrain decoration grass on `Grass`/`LeafyGrass` | Engine |

- **Wind.** Ring 0 patches tilt rigidly with phase-shifted wind waves; ring 1 shells shift horizontally by an offset proportional to the square of their height, the classic shell-texturing sway. Both are computed in a wind Actor in parallel and applied with `workspace:BulkMoveTo` serially.
- **Interaction.** Blades in the patch under the player bend away (per-vertex update on the closest patch only, time-sliced).
- **Transitions.** Ring boundaries fade with `Saturn`'s two-phase crossfade and density falloff, so no ring edge pops.
- **Budget.** Patch meshes and shell masks are created through a budget pool; static ones are baked when baking is available, which frees the editable budget for the rings that change.

## 4. Stress bench (HUD buttons, results logged and shown)

| Test | What it does | Reports |
|---|---|---|
| T1 Budget | Allocates 256 x 256 EditableImages until `nil`, then frees them | count, MB, whether `Destroy` returns budget at once |
| T2 Flawless raster | 256 shapes at 1024 x 1024, one thread versus 2, 4 and 8 Actors | ms, speedup, output hash |
| T3 ALLAN decode | Renders the exported ALLAN models at levels 0 to 2 | ms, events per row, hash |
| T4 Matte | Background removal on a generated green-screen image | ms per stage |
| T5 Uploads | 32 displayed images updated continuously through the upload scheduler | write ms, scheduled refreshes per frame |
| T6 Atlas | 1024 animated sprites drawn from one atlas through `ImageRectOffset/Size` | FPS, upload bytes per frame |
| T7 Giant canvas | 4096 x 4096 virtual canvas as 4 x 4 tiles with gutters on a `SurfaceGui`, pan and zoom | ms per tile, seams check |
| T8 LOD storm | 64 surfaces switching levels with two-phase fades | FPS |
| T9 Determinism | Every client hashes T2 and T3 outputs; the server compares | "bit-identical across N clients" or the first mismatch |
| T10 Server training | ALLAN statistics accumulation on the server in an Actor | ms per slice, progress |
| T11 Grass density | Blade density x1, x2, x4 | FPS, triangles |

**HUD, always on**: FPS, `Stats.FrameTime`, `HeartbeatTime`, `RenderCPUFrameTime`, `GetMemoryUsageMbForTag` for `GraphicsTexture`, `LuaHeap` and `GraphicsMeshParts`, live EditableImages and their pixel area, uploads this frame, busy Actors, and a capabilities panel (baking available, max image size, native codegen hints, which fallbacks are active).

## 5. Actors

- Client: 8 render workers (generic tile jobs: raster, ALLAN, matte), 4 grass geometry workers, 1 wind worker. Workers that own an EditableImage write it themselves in their serial phase; buffers sent between Actors arrive as copies, so jobs return small tiles.
- Server: 8 worldgen workers, 2 rock workers, 1 training worker.
- Pattern everywhere: compute in the parallel phase, touch engine objects (`WriteVoxels`, `WritePixelsBuffer`, `BulkMoveTo`, mesh edits) in the serial phase.

## 6. Build and checks

1. `tools/build_demo.sh`: converts `assets/liquid/*` to asset ModuleScripts, runs `rojo build demo/default.project.json -o build/UniverseMeadow.rbxlx`, and runs the checks below.
2. Type checking against the real Roblox API: `luau-lsp analyze` with the Roblox definitions (`globalTypes.None.d.luau`, the security level game scripts run at) and a Rojo sourcemap, so property names, method signatures and enum values are verified without Studio.
3. CLI tests for the pure generators (`WorldGen`, `GrassGen`, `SkyGen`): determinism, ranges, and both runtimes.
4. Every engine call that the audit marks NOT PUBLICLY SPECIFIED or that can fail at runtime is wrapped in `pcall`, reported in the capabilities panel, and has a fallback.

## 7. What the owner must do in Studio

- Open `build/UniverseMeadow.rbxlx` and press Play. In a published place, enable **Allow Mesh / Image APIs** in the experience's security settings.
- Studio, servers and plugins have no editable memory budget, so T1 reports the real limit only on a device in a published place.
